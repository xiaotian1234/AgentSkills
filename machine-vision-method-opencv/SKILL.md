# OpenCV 开源视觉工程方法论

## 什么时候用我

- 需要快速验证视觉算法、搭建原型、封装可复用模块。
- 传统视觉、DNN、ONNX、跨平台部署和性能优化需要取舍。

## 核心框架

### 1. 三层原型闭环

1. Notebook/脚本快速证明可行。
2. 模块化封装输入、参数、输出、可视化和测试样例。
3. 稳定后迁移到生产语言、加速后端或服务接口。

### 2. 传统视觉 + DNN 分工

传统视觉负责可解释、几何、测量、预处理和后验证；DNN 负责复杂纹理、语义、分类、检测和泛化。二者用数据和业务指标分工，不用信仰分工。

### 3. 跨平台可维护部署

管理 OpenCV 版本、构建选项、平台差异、加速后端、模型格式、输入输出契约和性能基线。

## 决策规则

1. 能用简单传统视觉稳定解决的，不急着上深度学习。
2. DNN 输出涉及定位或测量时，要加几何和物理 sanity check。
3. 原型每一步都要保存中间可视化。
4. 生产代码不要散落在 notebook 里。
5. 性能优化先 profile，再改算法或后端。
6. 跨平台项目要固定 OpenCV 版本和构建参数。
7. DNN 部署要验证输入尺寸、归一化、颜色通道、后处理和后端差异。
8. 所有阈值都应有样本依据和回放验证。
9. 图像 I/O、相机采集、异常处理和日志是系统的一部分。
10. 教程代码不能直接当产线代码。

## 检查清单

- [ ] 最小可运行原型存在。
- [ ] 每个模块有输入输出契约。
- [ ] 有可视化调试图和失败样例。
- [ ] 有 baseline 和回放数据集。
- [ ] 有版本、构建参数和平台说明。
- [ ] 有 P95/P99 性能数据。

## 反模式

- 把 demo 脚本直接部署。
- 不记录 OpenCV 版本和构建选项。
- BGR/RGB、归一化或坐标约定混乱。
- 过早微优化，没有 profile。
- DNN 结果不做后验证。

## 边界

OpenCV 适合开源工程和快速原型，但对商业视觉库算子、工业相机 SDK、PLC 集成和厂商支持不提供完整替代。详细提炼见 `references/framework.md`。
