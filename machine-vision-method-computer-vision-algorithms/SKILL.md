# 《Computer Vision: Algorithms and Applications》方法论

## 什么时候用我

- 需要判断某个视觉算法方案是否站得住。
- 配准、运动估计、3D、深度学习和传统视觉要做取舍。
- 需要把 demo 转成可验证实验设计。

## 核心框架

### 1. 成像链路优先

先回答图像如何形成，再回答算法能恢复什么。输出成像链、可见信息、不可见信息和主要噪声源。

### 2. 模型拟合与证据闭环

把问题写成：观测、变量、假设、损失、正则、异常点、优化器、评价指标。没有这些，模型名没有意义。

### 3. 几何-识别-时序路由

- 几何任务：坐标、标定、投影、变换族、残差。
- 识别任务：特征、分类、数据分布、泛化。
- 时序任务：运动、跟踪、漂移、同步、状态估计。

## 决策规则

1. 先判断任务是不是可从当前图像恢复，不可见信息不能靠模型魔法恢复。
2. 几何问题优先写出坐标系、相机模型和约束。
3. 匹配问题必须有外点处理和几何一致性验证。
4. 优化问题必须说明初始化、收敛、局部极小和残差分布。
5. 深度学习方案必须说明训练分布、测试分布和失败样例。
6. 指标必须和业务成本对齐，不只看平均准确率。
7. 对比算法必须在同一数据、硬件、指标和参数预算下比较。
8. 运行时间和内存是算法证据的一部分。
9. 新算法必须和简单 baseline 比较。
10. 每个上线结论都要有可复现数据和版本记录。

## 检查清单

- [ ] 成像链和问题可解性写清。
- [ ] 变量、观测、假设、损失函数和异常点机制写清。
- [ ] 有 baseline、ablation、stress set 和 failure set。
- [ ] 同时报告准确率、召回率、定位误差、速度、内存。
- [ ] 有失败样例和误差分解。

## 反模式

- 只给网络结构或算子名。
- 用漂亮可视化代替评价协议。
- 没有 ground truth 或替代验证标准。
- 把深度学习当作跳过几何和数据分析的理由。
- 不保留失败集。

## 边界

该方法论强在通用视觉算法评审，不负责具体工业产品授权、PLC 集成或厂商级技术支持。详细提炼见 `references/framework.md`。
