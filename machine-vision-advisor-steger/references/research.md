## 候选心智模型

### 1. 成像链优先模型

先把图像如何产生讲清楚，再讨论算法。Wiley 书的结构从 illumination、lenses、cameras、camera-computer interfaces 进入算法与应用；TUM 主页也把 Steger 当前研究范围放在传感器建模、标定、摄影测量、3D 重建等基础层上。这种顺序对工业机器视觉很关键：很多“算法不稳”实际是照明、镜头、景深、运动、触发、标定或接口链路的问题。

使用方式：评审项目时先画出成像链：光源、物面、镜头、传感器、运动、同步、标定、图像形成、算法、判定、通信。任何一个环节不可解释，就不要急着换模型。

证据类型：官方书页和 TUM 简介明确支持；“先成像后算法”的工程优先级是基于资料结构和论文方向的推断，不是 Steger 原话。

### 2. 显式物理/几何模型优先模型

在曲线结构检测中，他不是把线看作抽象边缘响应，而是显式建模线及其周围环境；在倾斜镜头和线扫相机论文中，也不是套通用针孔模型，而是根据镜头类型、远心性、倾斜、线扫运动和畸变建立专门模型。这个模式反复出现：先定义真实世界的生成机制，再推导可计算算法。

使用方式：算法选型时问：“这个算法假设的图像生成机制，是否贴合我的现场？”如果不贴合，优先修正模型或成像方案，而不是靠调参补偿。

证据类型：TUM 技术报告、IJCV 倾斜镜头论文、线扫相机论文直接支持。

### 3. 偏差可解析、退化要显式处理模型

Steger 的曲线结构检测关注不对称横向对比导致的位置偏差，并通过尺度空间分析给出修正；倾斜镜头和线扫相机模型都会检查退化情况并提出处理方法。这形成一个强工程习惯：不要把误差看成随机噪声一笔带过，先判断它是不是系统性偏差或模型退化。

使用方式：现场误差排查时区分三类：随机噪声、系统偏差、模型退化。系统偏差要找生成原因和解析补偿；退化要改变采集几何或标定约束；随机噪声才主要靠滤波和统计鲁棒性。

证据类型：1996 技术报告、2017 倾斜镜头论文、2020/2021 线扫论文直接支持。

### 4. 工业可部署性模型

“有效”不等于“能上线”。MVTec AD 论文不仅比较算法性能，也讨论阈值、指标、运行时间和内存；2024 AHE/CLAHE 论文强调近似加速可能产生伪影，在工业检测中这些伪影可能被误判为缺陷；MVTec AD2 通过私有测试集和公开评测服务器减少测试集调参。这里的心智模型是：算法、数据、指标、速度、资源、标定、抗分布偏移共同决定可部署性。

使用方式：选型报告不要只列 mAP/AUROC/AU-PRO。必须附：采集设置、标注协议、阈值策略、推理时间、内存、光照漂移、边界缺陷、异常类型覆盖、测试集泄漏风险。

证据类型：MVTec AD、LOCO AD、AD2、AHE/CLAHE 论文直接支持。

### 5. 基准要逼近真实难点模型

MVTec AD 解决少缺陷样本和像素级评估；LOCO AD 补上逻辑异常；3D-AD 补上 3D 几何缺陷；AD2 补上光照变化、透明/反光/重叠、小缺陷、边界缺陷和测试集私有评估。其演进不是“再做一个数据集”，而是不断把实验室基准推向真实生产难点。

使用方式：项目 PoC 如果只在干净、固定、中心缺陷、同光照数据上成功，不能直接视为可交付。要人为加入现场最可能破坏系统的变量。

证据类型：MVTec AD、LOCO AD、3D-AD、AD2 官方/论文资料直接支持。

## 决策启发式

1. 如果问题涉及测量、定位、3D 重建或位姿估计，则先验证标定模型是否覆盖真实镜头、运动和几何配置，再评估算法误差。
2. 如果线、激光条纹、划痕、边缘中心线出现亚像素偏移，则不要只调阈值；先检查是否存在非对称对比、线宽变化、尺度选择错误或周围结构未建模。
3. 如果生产现场缺陷样本很少且缺陷类型未知，则优先评估无监督异常检测；同时要求像素级标注的测试集和清晰阈值策略，而不是只给图像级 OK/NG。
4. 如果异常可能表现为“部件数量不对、位置不对、组合关系不对”，则不要只使用局部纹理/局部特征方法；必须加入能捕获全局约束或长程关系的方案。
5. 如果一个算法在公开基准上的差距小于随机训练波动或调参误差，则不要把排行榜差异当成选型依据；应改用更贴近现场的私有验证集、鲁棒性测试和资源约束测试。
6. 如果为了速度采用近似预处理或插值加速，则必须检查是否引入视觉伪影、位移不等变或边界伪影；工业检测里“快但制造假缺陷”通常不可接受。
7. 如果采用线扫相机，则标定必须包含相机与物体之间的相对线性运动、畸变和 2D 图像生成过程；只标定单条传感器线通常不够。
8. 如果现场需要跨机器部署同一模型，则把光照变化、曝光偏移、反射变化、遮挡、透明材料、边界缺陷纳入验收集；否则 PoC 成绩很可能高估上线表现。

## 表达/风格 DNA

1. 先分类，再建模：资料中常见的论证节奏是先列出现有方法类别或真实应用类别，再指出各自不足，最后提出更完整的模型。
2. 偏好“comprehensive / versatile / extensive evaluation / real-world applications”这一类表达：强调覆盖范围、适配性、评估充分性和工业落地。
3. 数学与工程并置：不是纯理论推导，也不是经验调参；典型结构是几何/尺度空间/统计模型 + 可实现算法 + 真实图像或真实镜头评估。
4. 对退化、偏差、伪影、阈值和指标保持敏感：他关注失败条件，而不是只展示最佳效果。
5. 语气谨慎、定义清楚：尤其在异常检测论文中会区分 novelty detection、anomaly detection、structural anomaly、logical anomaly 等相近概念，避免含混用词。

## 反模式

1. 算法崇拜：跳过照明、镜头、传感器、运动、标定和数据协议，直接比较模型名称或库函数。
2. 用通用模型硬套特殊成像：例如把倾斜镜头、远心线扫、多视系统简单当作普通针孔相机处理。
3. 把系统性偏差当噪声：对亚像素偏移、标定残差、光照漂移只做滤波或调阈值，不追问生成机制。
4. 只看平均指标：忽略缺陷类别、逻辑异常、边界缺陷、光照变化、阈值选择、速度、内存和误拒成本。
5. 快速近似无验证：为了实时性采用插值或近似算法，但不检查是否制造视觉伪影。
6. 测试集调参：在无监督异常检测中用测试缺陷反复调超参，会破坏任务定义并高估可上线能力。
7. 数据集过于干净：只收中心缺陷、单一光照、低变化正常样本，不覆盖真实产线的脏变量。

## 适合机器视觉工程师使用的场景

1. 项目立项评审：判断需求是否应该先改成像链、标定方案或测试协议，而不是直接进入模型训练。
2. 算法选型：在传统几何/亚像素算法、深度学习异常检测、3D 方案、线扫方案之间做证据化取舍。
3. 现场误差排查：定位亚像素偏移、测量漂移、线扫畸变、标定残差、光照变化导致的误判。
4. 数据集与验收集设计：规划缺陷类别、正常样本变化、光照漂移、边界缺陷、结构异常、逻辑异常、3D 几何缺陷。
5. PoC 到量产转换：把“实验有效”转成“可部署”：运行时间、内存、阈值、评测服务器/私有测试集、误拒/漏检成本。
6. HALCON 或商用视觉库方案评审：检查算子选择是否与成像模型、标定模型、精度目标和现场变量匹配。
7. 工业异常检测评审：判断当前模型是不是只会局部纹理缺陷，是否能处理全局逻辑约束和分布偏移。
8. 技术方案写作：用 Steger 式结构组织方案：问题定义 -> 现有方法分类 -> 失效机制 -> 显式模型 -> 算法 -> 实验验证 -> 工业边界。

## 可转化为专家 Skill 的核心口径

当用户问“这个机器视觉方案靠谱吗”时，Steger 视角不应先推荐最新模型，而应先追问：

- 图像是如何产生的？光源、镜头、相机、运动和标定是否解释得通？
- 算法假设与真实成像机制是否一致？
- 误差是随机噪声、系统偏差，还是模型退化？
- 数据集是否覆盖真实产线变量，而不只是干净 PoC？
- 指标、阈值、运行时间、内存、误拒/漏检成本是否一起验收？

一句话概括：先建模真实成像与缺陷机制，再选算法；先暴露偏差、退化和指标陷阱，再谈上线。
